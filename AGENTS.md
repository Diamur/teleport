# TelePort Portal — архитектура проекта (для Codex)

## Что это
TelePort — портал реального времени: веб-клиент + API авторизации + WebSocket-сигналинг (для чата/присутствия/звонка и т.п.).
Проект собран как **monorepo**: в репозитории рядом лежат серверная часть и публичная часть сайта.

> ВАЖНО ДЛЯ CODEX  
> В репозитории **две части находятся в одном месте**: `teleport-server/` и `public/`.  
> На прод-сервере эти части **физически разнесены** по разным путям (см. раздел “Маппинг на сервере”).  
> Поэтому Codex должен оперировать путями внутри репозитория и понимать, что деплой раскладывает их в разные директории на сервере.

---

## Состав проекта (2 части)

### 1) `teleport-server/` — сервер (Node.js)
Назначение:
- WebSocket сервер (сигналинг/присутствие/события)
- логика комнат/онлайна/конференций
- обычно слушает локальный порт (например `127.0.0.1:3000`), наружу отдаётся через Nginx reverse proxy (например `/ws`)

Ожидаемые элементы:
- точка входа сервера (например `index.js`/`server.js`)
- конфиг/ENV (если есть)
- systemd-service на проде (если используется)

### 2) `public/` — публичная часть сайта (Nginx + PHP + статика)
Назначение:
- `client/` — фронтенд (HTML/JS/CSS)
- `api/` — PHP-эндпоинты (логин/сессии/служебные методы)
- `data/` — файлы данных (если проект хранит что-то файлово)
- `index.php`, `README.md`, `favicon.ico` и т.п.

## Маппинг на сервере (как разложено в проде)

На сервере эти части НЕ обязаны лежать рядом.

- `public/` из репозитория разворачивается в веб-корень Nginx, например:
  - `/var/www/w-tp.ru/public/`

- `teleport-server/` из репозитория разворачивается в отдельную директорию (не веб-корень), например:
  - отдельная папка под Node-сервис (путь задаётся деплоем / systemd)
  - сервер слушает localhost-порт, а Nginx проксирует запросы на него

Codex должен учитывать:
- при изменениях в `public/**` мы влияем на то, что отдает Nginx/PHP
- при изменениях в `teleport-server/**` мы влияем на Node-сервис (и его рестарт/перезапуск)

## Потоки запросов (схема)

### Веб-клиент
1) Пользователь открывает `/` (из `public/`)
2) Клиентские скрипты из `public/client/` подключаются (например `/client/script.js?v=1`)
3) Для авторизации/сессий клиент дергает `public/api/**` (PHP)
4) Для realtime-событий клиент подключается к WebSocket (обычно `/ws` → Nginx → `127.0.0.1:<port>`)

### Nginx (типовая роль)
- раздает `public/` как сайт
- проксирует WebSocket endpoint (например `/ws`) в Node.js сервер
- PHP обрабатывает `/api/**` (или по правилам конфига)

## Данные и состояние (типовой расклад)
- Сессии/пользователи могут храниться в файловом виде в `public/api/` (если так реализовано)
- Статические данные/логика клиента — в `public/client/`
- Файловые данные проекта — `public/data/` (если используется)

## Взаимодействие с владельцем (когда нужны проверки на сервере/локально)

Если для диагностики/подтверждения гипотез нужно выполнить команды в консоли (локально на ПК или на сервере) и получить фактические результаты (логи, вывод команд, список файлов, права, порты, статус сервисов) — владелец проекта может это сделать и прислать результаты в чат.

Codex:
- формулируй команды **в одном копируемом блоке**, без лишнего текста;
- указывай **где выполнять**: Windows (PowerShell) / Linux (bash) / сервер (SSH);
- пиши, **какой результат** ожидаешь увидеть и **что именно прислать** (полный вывод, конкретные строки, скрин, файл лога);
- если команды потенциально опасны — используй только безопасные варианты (read-only), не давай команды на удаление/перезапись без явной необходимости.

## Правила для Codex при изменениях
1) Всегда ориентируйся на структуру **репозитория** (monorepo).
2) Помни, что на сервере `public/` и `teleport-server/` разнесены — не делай выводов “они рядом по пути” на проде.
3) Если меняется `teleport-server/**`, учитывай необходимость перезапуска Node-сервиса (systemd/pm2/и т.п. — зависит от деплоя).
4) Если меняется `public/**`, это влияет на сайт/клиент/PHP-API (обычно без рестарта Node).
5) Не перемещай папки и не переименовывай корневые директории без явной необходимости: `teleport-server/` и `public/` — якоря архитектуры.
